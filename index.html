Three disciplines, one path

Software Architect

Decisions written down, systems modeled before they're built.

What I already work with

  • Architecture decision records for every choice that's hard to undo.
  • C4, ER, sequence, state and Event Storming models, kept as Mermaid next to the code.
  • Requirements specs following IEEE 830 and ISO/IEC/IEEE 29148, generated from a project template I maintain.
  • Distributed systems from the course: middleware, invocation semantics, idempotency, two-phase commit versus sagas, logical clocks.

Next: design distributed systems end to end, with every trade-off on paper before the first line of code.

AI Engineer

Agents that do real work, inside guardrails I can explain.

What I already work with

  • Claude Code as an agent runtime: skills, hooks, subagents and MCP servers.
  • Multi-agent pipelines that split extraction, generation and verification into separate roles.
  • An always-on personal assistant on a Linux box, reachable over Telegram, with Notion as its memory.
  • A specification for an agent harness: decisions, contracts and an evaluation corpus built from real tasks.

Next: an LLM gateway with retries and idempotency keys, token-bucket rate limiting and streaming with backpressure.

Orange Team

The bridge between how systems get attacked and the people who build them.

What I already work with

  • Computer Networks I and II: static and dynamic routing, IPv4 and IPv6, CIDR, NAT and PAT, TCP and congestion control.
  • Agent security in practice: prompt-injection-aware design, least privilege, layered permission hooks that fail closed, isolated users and private network access over Tailscale.

Next: threat modeling and secure-by-design reviews as a default step of architecture work.
